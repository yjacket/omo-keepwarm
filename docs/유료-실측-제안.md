lane을 `verified`로 올리기 전에 필요한 유료 측정 계획이다. **아직 실행하지 않았다.** 개발과 QA에서는 실제 공급자에 유료 요청을 보내지 않는다. 이 측정은 [활성화 단계](유휴-캐시-만료-정책.md#shadow에서-활성화로-가는-단계)의 ②에 해당한다.

## 1. Anthropic API 5분 lane 읽기 갱신

- **질문.** 5분 TTL 캐시를 읽으면 수명이 다시 5분으로 늘어나는가. 1시간 lane은 확인했지만(n = 2) 5분 lane은 재지 않았다.
- **절차.**
  1. 약 2만 토큰 접두부로 쓰기 요청 1회를 보낸다.
  2. 4분 30초 간격으로 같은 접두부를 `max_tokens` 0으로 3회 읽는다.
  3. 요청마다 `cache_read_input_tokens`, `cache_creation_input_tokens`를 기록한다.
- **판정.** 세 번 모두 적중(읽기가 접두부 전체)이면 갱신된다. 첫 쓰기 뒤 5분이 지난 두 번째 읽기가 적중하는 것이 핵심이다.
- **비용.** 약 $0.1-0.3(모델 단가에 따라).
- **결과 반영.** 갱신이 확인되면 `lanes.anthropic-api.verified = true`를 쓸 수 있다.

## 2. Codex warmer가 생긴 뒤 검증

[senpi upstream 요구](senpi-upstream-요구.md)의 2번이 생긴 뒤에만 한다.

1. 같은 `prompt_cache_key`로 본요청 1회, 27분 뒤 warmer 1회, 다시 27분 뒤 본요청 1회를 보낸다.
2. 마지막 본요청의 cached tokens가 접두부 전체인지 본다.
3. `store: false`, `previous_response_id` 없음이 실제 페이로드에 있는지 본다.
4. 대화 기록과 UI에 흔적이 없는지 본다.

- 결과(요청별 usage, 비용, 판정)를 보고서로 남긴다. research/는 보존 폴더라서 새 폴더에 둔다.
- 측정 뒤 config를 바꾸는 것은 사용자가 결정한다.
