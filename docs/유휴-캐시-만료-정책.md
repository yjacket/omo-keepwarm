사용자가 자리를 비운 동안 프롬프트 캐시를 언제까지 데우고 언제 만료시킬지 정하는 규칙이다. 근거는 [조사 보고서](#근거)에 있다.

## 기본 정책

| lane | 캐시 수명(TTL) | 데우기 중단(만료) 시점 | 근거 |
|---|---|---|---|
| 5분 lane | 5분 | **30분** | 사용자 결정. 아래 산식으로는 r = 0.045 부근의 값 |
| 30분 lane (GPT-5.6 이상) | 30분 | **약 1시간 50분** (제안) | 산식 계산값. r = 0.08 |
| 1시간 lane (Claude 구독 본대화) | 60분 | **4시간** | 사용자 결정. 산식으로는 r = 0.025일 때 5시간 30분, r = 0.04일 때 4시간 35분 |

lane별 TTL과 r 기본값은 [모델별 캐시 TTL 기본값](모델별-캐시-TTL-기본값.md) 페이지에 있다.

## 산식

핑을 보낼 시점마다 다음 부등식 하나만 확인한다.

> **다음 핑 간격 안에 돌아올 확률 > 핑 1회 비용 ÷ 재작성 1회 비용** 이면 데운다. 아니면 그 시점에서 만료시킨다.

- **오른쪽 r (환경값).** lane의 가격비, 즉 캐시 읽기 가격 ÷ 캐시 쓰기 가격이다. 핑은 맥락 전체를 캐시에서 한 번 읽고, 재작성은 맥락 전체를 다시 쓴다. 둘 다 맥락 크기에 비례하므로 r은 맥락 크기와 상관없다.
- **왼쪽 h(t) (행동값).** 누적 복귀율 곡선 F에서 `h(t) = [F(t+간격) − F(t)] ÷ [1 − F(t)]`로 계산한다.
- **만료 시점 T\*.** h(t) < r이 처음 성립하는 핑 시점이다. 곡선이 시간이 갈수록 완만해지므로(관측도 그렇다) 처음 넘는 지점이 곧 마지막 지점이다. 이 조건에서는 기존 DP에서 파킹을 뺀 답과 같다.

![산식이 작동하는 방식](images/expiry-mechanism.png)

- **왼쪽 그림.** 관측된 복귀율(09-17~23, 유휴 162건)과, 세 숫자로 만든 곡선이다.
- **오른쪽 그림.** 각 lane의 h(t)가 점선 r 아래로 내려가는 곳이 만료 시점이다.

## 사용자 행동은 세 숫자로 넣는다

| 입력 | 뜻 | 현재값 |
|---|---|---|
| p | 하루 안에 결국 돌아오는 비율 | 81% |
| m | 돌아오는 사람의 중앙 복귀 시간 | 10.5분 |
| t90 | 돌아오는 사람의 90%가 돌아오는 시간 | 2시간 20분 |

확장은 이 세 숫자로 곡선 `F(t) = p × Φ((ln t − ln m) ÷ s)`, `s = (ln t90 − ln m) ÷ 1.28`을 만든다. 현재 관측과의 차이는 ±2%p 이내다. 세 숫자는 사람이 직접 넣어도 되고, 별도 측정 시스템이 파일로 갱신해도 된다.

![복귀 패턴에 따른 만료 시점](images/expiry-vs-return-pattern.png)

- **결국 돌아오는 비율이 높아지면(오른쪽)** 모든 lane에서 더 오래 데운다.
- **복귀가 느려지면(왼쪽)** lane마다 방향이 갈린다. 1시간 lane은 더 오래 데우고, 5분 lane은 더 일찍 멈춘다. 5분 lane은 몇 분 안에 돌아올 확률만 보는데, 복귀가 몇 시간 쪽으로 퍼지면 그 확률이 줄기 때문이다.

## lane별 비용 차이는 무시해도 되나

맥락 크기는 무시해도 된다. **lane의 가격비 r은 무시하면 안 된다.** 특히 5분 lane은 r이 0.02면 1시간 8분, 0.08이면 18분으로 만료 시점이 네 배 가까이 달라진다. 그래서 r은 lane마다 값 하나로 입력받는다.

![가격비 r에 따른 만료 시점](images/expiry-vs-cost-ratio.png)

| r | 5분 lane | 30분 lane | 1시간 lane |
|---|---|---|---|
| 0.0125 | 1시간 44분 | 5시간 51분 | 8시간 15분 |
| 0.025 | 59분 | 3시간 36분 | 5시간 30분 |
| 0.04 | 36분 | 2시간 42분 | 4시간 35분 |
| 0.05 | 27분 | 2시간 15분 | 3시간 40분 |
| 0.08 | 18분 | 1시간 48분 | 2시간 45분 |

## 확장의 동작

1. **유휴 시작.** 자식 작업과 대기 중인 입력 없이 에이전트가 멈추면 t = 0으로 둔다(마지막 실제 요청 시각).
2. **핑 시점.** 간격(TTL − 여유)마다 t < T\*이면 최소 핑(캐시 읽기, 출력 1토큰)을 보내고, 아니면 아무것도 하지 않는다. 기본 간격은 5분 lane 4분 30초, 30분 lane 27분, 1시간 lane 55분이다. Anthropic의 TTL은 요청 시작부터 재므로 응답 생성 시간까지 여유에 넣는다.
3. **복귀.** 사용자 입력이 오면 에피소드가 끝난다. 핑과 확장 자신이 보낸 명령은 복귀로 세지 않는다.
4. **파킹.** 기본으로 꺼 둔다. 켜면 T\*에서 만료 대신 파킹한다. 5분 lane에서는 비용상 파킹이 유리하지만 재설명 부담과 복원 지연이 붙는다.
5. **중단 조건.** 다음 중 하나라도 해당하면 데우기를 멈춘다.
   - 모델, lane, effort가 바뀜(캐시가 바뀐다)
   - rate limit 또는 오류
   - 에피소드당 핑 상한(T\* ÷ 간격 + 1)이나 일일 상한에 도달
   - 맥락이 작음(예: 2만 토큰 미만은 생략)
6. **기록.** 결정마다 (t, lane, h, r, 행동)을, 에피소드마다 결과(복귀 시각, 종료, 관측 중단)를 남긴다. 이 기록으로 p, m, t90을 다시 계산한다. 핑 비용은 핑 요청의 사용량으로, 이득은 복귀 첫 요청의 캐시 적중으로 확인되므로 확장의 효과를 자기 기록만으로 측정할 수 있다.

## 주의

- **캐시가 이미 무효면 데우기가 헛돈다.** 다음 요청의 앞부분이 바뀌면 데운 캐시를 쓰지 못한다. 예를 들어 모델·effort 전환, 도구 목록 변경, 마지막 턴에서 메모리 파일을 새로 만든 경우(시스템 프롬프트가 다시 만들어진다)다.
- **5분 lane의 갱신 여부.** 5분 lane에서 캐시를 읽으면 TTL이 갱신되는지는 직접 재지 않았다. 1시간 lane은 55분에 읽으면 갱신되는 것을 실측으로 확인했다(n = 2).
- **r 값의 성격.** 5분 lane과 GPT lane의 r은 API 목록가 비율에서 가져온 값이다. 구독 quota의 실제 비율은 Claude 1시간 lane(약 0.022~0.026)만 측정했다.
- **모드별 곡선.** 대화형과 자율 실행은 복귀 곡선이 다르다. 모드별로 세 숫자를 따로 받는 것이 좋다.
- **senpi 내장 데우기와의 관계.** senpi 내장 `cache-keepalive`는 API 키로 쓰는 Anthropic lane만 지원한다. 주력 lane인 Claude 구독(Agent SDK 경유)과 Codex에는 데우기 요청을 보낼 경로를 새로 만들어야 한다.
