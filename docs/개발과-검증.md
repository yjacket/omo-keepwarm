# 개발과 검증

이 저장소에서 코드를 고치고 확인하는 방법이다. 설치된 keepwarm을 다루는 방법은 [운영과 문제 해결](운영과-문제-해결.md)에 있다.

## 구조

| 경로 | 역할 |
|---|---|
| `bin/omo-keepwarm.mjs` | CLI 진입점. `src/cli/<명령>.mjs`로 넘긴다. 모르는 명령은 64, 명령 파일이 없으면 70으로 끝난다 |
| `extension/stub.ts.tpl` | `~/.omo/agent/extensions/omo-keepwarm.ts`로 렌더링되는 스텁. 버전과 경로를 담지 않는다. `app/current.json`의 root, 실패하면 lkg root를 불러온다 |
| `extension/import-fresh.mjs` | 스텁이 릴리스를 `?v=<mtime>`로 불러오게 하는 도우미. senpi의 jiti/vm 안에서는 동적 import가 막혀 있어서 필요하다 |
| `extension/keepwarm.mjs` | 세션 안 진입점. 이벤트를 상태기에 잇고, heartbeat, 인스턴스 토큰, loaded 표시, config 게이트, 자동 보정을 맡는다 |
| `src/episode.mjs` | 자리 비움 에피소드 상태기. 열기, 세그먼트, tick, 핑, 중지 사유, 재로드 복원 |
| `src/provenance.mjs` | 턴이 사람 것인지 자동인지 판정한다 |
| `src/policy.mjs`, `src/lanes.mjs` | 산식 T\*, 격자 양자화, lane 분류와 기본값 |
| `src/warm.mjs` | pi-ai `warmPromptCache` 호출, 접두부 대조, 비용과 적중 계산 |
| `src/config.mjs` | config.json과 behavior.json 읽기, 검증, expiry와 habit 해석 |
| `src/records.mjs`, `src/status.mjs`, `src/ledger.mjs` | 기록 v1, 상태 스냅샷, 비용 장부와 하루 장부 |
| `src/install.mjs`, `src/cli/*.mjs` | install, update, uninstall, doctor, render-stub와 나머지 명령 |
| `src/calibrate.mjs`, `src/report.mjs` | 습관 보정(Aalen-Johansen)과 보고 |
| `src/safe.mjs`, `src/fsx.mjs`, `src/paths.mjs` | 오류 격리, 원자적 쓰기, 경로 |
| `test/` | node:test 단위 테스트. `test/helpers/fake-host.mjs`가 가짜 pi, ctx, 시계, pi-ai를 준다 |
| `qa/` | 실제 senpi로 도는 시나리오와 그 장치 |
| `research/` | 연구 원자료. 바이트를 그대로 보존한다 |

기록, 설정, 상태 파일의 필드는 [기록과 상태 계약](기록과-상태-계약.md)에 있다.

## 규칙

- Node 24 이상, ESM `.mjs`다. npm 의존성은 없다.
- `src/`와 `extension/*.mjs`는 `node:` 내장 모듈과 상대 경로만 import한다. 호스트 패키지(`@earendil-works/*`, `@code-yeongyu/*`)는 스텁 템플릿만 쓴다. `test/imports.test.mjs`가 지킨다.
- 대화 기록, 턴, UI에 흔적을 남기는 API(`sendMessage`, `appendEntry`, `setStatus`, `notify`, `ctx.ui`)는 쓰지 않는다.
- 이벤트 핸들러는 모두 `src/safe.mjs`를 거친다. 오류는 `logs/errors.log`에 한 줄 남기고 호스트로 던지지 않는다. 재로드로 은퇴한 이전 세대의 오류("stale extension generation")는 그 인스턴스만 끄고 기록하지 않는다.
- 테스트는 가짜 시계만 쓴다. 고정 sleep은 쓰지 않는다.
- `research/**`는 고치지 않는다(`.gitattributes`의 `research/** -text`).
- 커밋 메시지는 영어 소문자 Conventional Commits다(`feat(episode): …`, `fix: …`, `docs: …`).

## 단위 테스트

```sh
npm test
node --test --test-reporter=tap test/episode.test.mjs
```

`test/docs-consistency.test.mjs`는 README의 lane 표를 `classifyLane()`과, README의 `expiry` 출력 블록을 실제 CLI 출력과 대조하고, 문서의 상대 링크가 살아 있는지 본다. lane 기본값이나 `expiry` 출력을 바꾸면 README도 함께 고친다.

## 실사용 시나리오

`qa/`의 시나리오는 실제 senpi 프로세스를 띄우고, 요청을 로컬 mock Anthropic 서버로 돌린다. 유료 요청은 없다.

- **준비.** `senpi`가 PATH에 있어야 한다. s7은 Windows에서 .NET Framework의 `csc.exe`로 ConPTY 호스트(`qa/conpty-host.cs`)를 빌드한다. `@earendil-works/pi-pty`는 darwin-arm64 prebuild만 있어서 Windows에서는 진짜 TTY를 만들지 못한다.
- **격리.** 매 실행이 임시 keepwarm 홈, 임시 agent 폴더, `--offline`을 쓴다. `qa/fetch-redirect.ext.mjs`가 `https://api.anthropic.com`을 mock으로 돌리고, 다른 호스트로 가는 요청은 막고 block 로그에 남긴다. 모델을 고르는 짧은 실행에도 이 확장을 싣는다. 모든 시나리오가 block 로그 0줄을 확인한다.
- **빠른 lane.** `qa/fixtures/config-shadow.json`과 `config-on.json`은 anthropic-api lane을 TTL 12초, 간격 4초, 격자 [0, 0.2, 0.4, 0.6]분으로 덮어써서 시나리오가 1분 안에 끝나게 한다. `behavior-fast.json`은 `qa/tune-fast-habit.mjs`가 만든다.
- **결과.** 시나리오마다 `result.json`(`{ scenario, pass, checks }`), mock 요청 로그, keepwarm 기록 사본, 세션 사본, senpi 출력, `cleanup.txt`를 남긴다. 모든 check가 통과해야 exit 0이다.

| 시나리오 | 확인하는 것 |
|---|---|
| `qa/smoke.mjs` | 장치 자체. senpi RPC가 mock으로 턴을 끝내고 외부 요청이 0이다 |
| `s1-shadow` | shadow에서 에피소드가 열리고 would_warm 2회 이상, expire, 사람 복귀로 닫힌다. warm 요청은 0이다 |
| `s2-on` (`--inject 429`) | on과 검증된 lane에서 warm 요청의 system과 tools가 직전 대화와 같고 캐시에 적중한다. 429를 주면 rate_limit으로 멈추고 그 뒤 요청이 없다 |
| `s3-provenance` | 자동 턴 5종은 에피소드를 닫지 않고, 사람 입력만 human_return으로 닫는다 |
| `s4-stops` (`--case a,b,…`) | 중지 조건 7종: model_change, effort_change, rate_limit, provider_error, cache_miss, episode_usd_cap, duplicate_warmer |
| `s5-reload` | 에피소드 도중 reload해도 같은 에피소드가 이어지고 가짜 복귀가 없다 |
| `s6-inert` | print 모드와 worker 세션은 아무것도 쓰지 않는다 |
| `s7-tui` | 실제 TUI에서 입력 출처가 interactive이고, 화면에 keepwarm 흔적이 없다 |
| `s8-install-real-senpi` | 실제 CLI로 설치하면 senpi가 스텁을 발견해 불러온다. update는 스텁을 건드리지 않고, uninstall과 `--purge`가 동작한다 |
| `s9-cli` | status, report, calibrate, expiry, habit 출력과, expiry와 habit 변경이 재로드 없이 다음 에피소드에 반영되는 것 |

```sh

```

## 개발 중인 코드로 senpi 띄우기

`render-stub`은 체크아웃을 가리키는 스텁을 만든다. 실제 홈에 설치하지 않고 확인할 때 쓴다.

```sh
OMO_KEEPWARM_HOME=<임시 폴더> node bin/omo-keepwarm.mjs render-stub --dev-root <체크아웃> --out <임시 폴더>/omo-keepwarm.ts
OMO_KEEPWARM_HOME=<임시 폴더> senpi -e <임시 폴더>/omo-keepwarm.ts
```

**`OMO_KEEPWARM_HOME`을 반드시 임시 폴더로 지정한다.** `render-stub`은 그 홈의 `app/current.json`을 체크아웃으로 바꿔 쓴다. 지정하지 않으면 실제 홈의 current.json이 개발 체크아웃을 가리키게 된다.

## 실제 홈에 반영하기

- 버전은 `package.json`의 version과 소스 해시를 합친 값이다(예: `0.1.0+02203bd3`). 소스가 같으면 버전도 같다.
- 코드를 고친 뒤에는 `node bin/omo-keepwarm.mjs update`를 실행한다. 새 릴리스를 `app/releases/<버전>/`에 복사하고 `app/current.json`만 바꾼다. 스텁은 그대로라 열린 세션은 재로드되지 않고, 새 세션이나 다음 재로드부터 새 버전을 쓴다.
- 다른 세션이 바쁘면 3으로 끝난다. 흐름과 대처는 [운영과 문제 해결](운영과-문제-해결.md)에 있다.
