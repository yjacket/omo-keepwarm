keepwarm이 쓰는 파일의 모양이다. 보정 분석가와 omo-health가 이 계약을 믿고 읽는다. 기준 코드는 `src/records.mjs`(`SCHEMA`), `src/config.mjs`, `src/status.mjs`, `src/ledger.mjs`다.

## 파일 위치

홈은 `OMO_KEEPWARM_HOME`, 없으면 `~/.omo-keepwarm`이다.

| 경로 | 쓰는 쪽 | 방식 |
|---|---|---|
| `config.json` | install, `expiry set`, `habit set` | 원자적 교체 |
| `behavior.json` | `calibrate --write`, 자동 보정 | 원자적 교체 |
| `records/<YYYY-MM>/<sessionId>.jsonl` | 확장 | 추가만 |
| `status/<sessionId>.json` | 확장 | 원자적 교체 |
| `status/_global.json` | 확장 | 원자적 교체 |
| `ledger/spend-<date>.jsonl` | 확장 | 추가만 |
| `ledger/day-<date>.jsonl` | 확장 | 추가만 |
| `logs/errors.log` | 확장 | (이름, 메시지)당 1줄 |
| `logs/stub.log` | 스텁 | 로드 실패당 1줄 |
| `app/current.json`, `app/releases/<version>/`, `app/loaded/<version>` | install, 스텁 | |

날짜는 로컬 `YYYY-MM-DD`다. 잠금은 없다. 모든 공유 파일은 추가만 하거나 원자적으로 바꾼다.

## 기록 v1

한 줄이 JSON 하나다. 공통 필드는 `{ v: 1, ts: ISO 시각, type, session: <sessionId> }`다. type별 필드는 모두 들어가고, 값이 없으면 `null`이다. 모르는 type은 쓰지 않는다. 프롬프트 본문, 도구 인자, 자격증명, 헤더는 넣지 않는다.

| type | 필드 |
|---|---|
| `session` | reason, mode, sessionKind, uiMode, keepwarmVersion, cwd, restored |
| `episode_open` | episode, awayStartMs, openedBy, lane, provider, api, model, thinking, contextTokens, habit, r, expiry, maxPings, mode, warmPath, verified |
| `segment_open` | episode, segment, reason, anchorMs, lane, model, eligible, disabledReason |
| `decision` | episode, segment, tick, tAwayMin, hazard, r, action, reason, lateByMs |
| `ping` | episode, segment, tick, ok, hit, usage, costUsd, durationMs, error, stale |
| `warm_stop` | episode, segment, reason |
| `turn` | episode, segment, kind, source, startMs |
| `marker` | episode, kind, atMs |
| `episode_close` | episode, closedAtMs, awayMin, kind, source, detail, segments, turns, decisions, wouldWarm, pings, costUsd, virtualUsd, expired, coveredAtReturn, coldWithoutWarm, markers |
| `return_usage` | episode, model, input, output, cacheRead, cacheWrite, sinceRealAnchorSec |

중첩 필드는 아래 키만 남는다.

| 필드 | 키 |
|---|---|
| `episode_open.habit` | p, mMin, t90Min, source |
| `episode_open.expiry` | formulaMin, autoMin, requestedMin, effectiveMin, source |
| `ping.usage` | input, output, cacheRead, cacheWrite |
| `ping.error` | kind, message, status |
| `episode_close.markers` | 최근 32개, 각각 kind, atMs |

값의 범위:

- `episode`는 `<session>:<seq>`다.
- `episode_open.openedBy`: `settled`, `restore_failed`.
- `segment_open.reason`: `episode_open`, `after_turn`, `children_drained`, `reload`.
- `decision.action`: `warm`, `would_warm`, `expire`, `skip`.
- `turn.kind`: `automated`, `unattributed`.
- `episode_close.kind`: `human_return`, `censored`.
- `ping.error.kind`: unsupported, prefix_mismatch, rate_limit, timeout, aborted, auth, provider_error.
- `expiry.source`: `auto`, `manual`, `auto-invalid-habit`.

## config.json

| 키 | 형식 | 기본값 |
|---|---|---|
| `v` | 1 | 1 |
| `mode` | `"off"` \| `"shadow"` \| `"on"` | `"shadow"` |
| `maxUsdPerEpisode` | 0 이상 숫자 | 0.5 |
| `maxUsdPerDay` | 0 이상 숫자 | 3 |
| `expiry` | `{ <키>: "auto" \| 0 이상 분 }` | `{}` |
| `habit` | `"auto"` \| `{ p, medianMinutes, t90Minutes }` | `"auto"` |
| `lanes` | `{ <laneId>: { ttlSeconds?, intervalSeconds?, r?, minContextTokens?, verified?, grid? } }` | `{}` |

- 파일이 없으면 mode는 `off`다.
- 잘못된 필드는 기본값으로 바꾸고 doctor가 WARN으로 알린다. 모르는 키는 보존한다.
- `expiry` 키는 TTL 등급이 여럿인 lane(`anthropic-api`, `openai-api`, `codex-subscription`)이면 `<laneId>:<등급>`(예: `anthropic-api:5m`), 그 밖은 lane id다. 찾을 때는 `<id>:<등급>`을 먼저, 없으면 `<id>`를 본다. 숫자는 격자로 맞춰 쓴다.
- `lanes.<id>.grid`는 0으로 시작하는 오름차순 숫자 배열이어야 한다. 양수가 아닌 ttlSeconds 같은 값은 무시한다.

## behavior.json

```json
{ "v": 1, "p": 0.81, "mMin": 10.5, "t90Min": 140, "humanReturns": 42, "updatedAt": "2026-09-29T00:00:00.000Z" }
```

`habit`이 `auto`이고, 세 값이 유효하고(0 < p ≤ 1, 0 < mMin < t90Min), `humanReturns` ≥ 30이고, `updatedAt`이 28일 이내일 때만 쓴다(출처 observed). calibrate가 그 밖에 추정 정보를 더 넣을 수 있다.

## 상태 스냅샷

**세션 파일** `status/<sessionId>.json`:

```text
{ v: 1, ts, session, phase, lane, mode, episode, tAwayMin, nextTickMs, self: "active"|"disabled", episodeState }
```

`episodeState`는 재로드 복원용이다. 세션이 끝날 때 episodeState가 없으면 파일을 지우고, 있으면 phase `detached`로 남긴다.

**전역 파일** `status/_global.json`:

```text
{ v: 1, ts, staleAfter, level: "ok"|"warn", text,
  detail: { mode, sessions: { count, idle, warming },
            today: { episodes, humanReturns, wouldWarm, pings, usd },
            errorsToday, lanes: { <laneId>: "on"|"shadow"|"observe"|"off" } } }
```

- 세션 파일과 장부의 순수 집계다. 세션은 ts가 15분 이내인 파일만 센다.
- heartbeat는 5분마다, `staleAfter`는 `ts + 15분`이다.
- `level`은 오늘 오류가 있거나 disabled 세션이 있으면 `warn`이다.
- `text` 형식: `keepwarm <mode> · <n> sessions (<idle> idle) · today <e> episodes, <h> returns, <p> pings, $<usd>`.

## omo-health 읽기 규칙

omo-health는 `status/_global.json`을 읽기만 한다.

| 상태 | 표시 |
|---|---|
| 파일 없음 | 아무것도 표시하지 않는다 |
| `staleAfter`가 지났거나 파일이 깨짐 | `keepwarm: unknown` |
| 그 밖 | `text`와 `level` |

keepwarm은 omo-health 파일을 install의 바쁜 세션 검사에서만 읽고, 쓰지 않는다.

## 장부

- `ledger/spend-<date>.jsonl`: `{ v: 1, ts, session, episode, usd, virtual }`. shadow의 가상 비용은 `virtual: true`다. 하루 상한은 모든 세션의 줄을 합쳐 본다.
- `ledger/day-<date>.jsonl`: `{ v: 1, ts, episodes, humanReturns, wouldWarm, pings, usd }`. `_global.json`의 today가 이 합계다.
