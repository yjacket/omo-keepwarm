# 운영과 문제 해결

설치된 keepwarm을 확인하고, 경고를 읽고, 끄는 방법이다. 명령 목록과 설치 방법은 [README](../README.md)에 있다. 아래 `omo-keepwarm`은 저장소의 `node bin/omo-keepwarm.mjs`와 같다.

## 확인하는 곳

| 알고 싶은 것 | 명령이나 위치 |
|---|---|
| 전체 상태 한 줄 | `omo-keepwarm status` 첫 줄. omo-health의 keepwarm 줄도 같은 스냅샷(`status/_global.json`)을 읽는다 |
| 세션별 phase, lane, mode | `omo-keepwarm status`의 세션 목록 |
| 최근 에피소드, 복귀, 반사실 절감 | `omo-keepwarm report [--days 7] [--json]` |
| 설치 상태 점검 | `omo-keepwarm doctor` |
| 원본 기록 | `~/.omo-keepwarm/records/<YYYY-MM>/<sessionId>.jsonl` |
| 오류 | `~/.omo-keepwarm/logs/errors.log`(확장), `logs/stub.log`(스텁이 릴리스를 못 불러옴) |

## 세션 phase

| phase | 뜻 |
|---|---|
| `BUSY` | 에피소드 없이 턴이 도는 중이다 |
| `HELD` | 턴은 끝났지만 아직 에피소드를 열 수 없다(대기 입력, 곧 올 턴, 재로드 직후). 다음 settle에 연다 |
| `ARMED` | 에피소드가 열려 있고 다음 tick을 기다린다 |
| `PINGING` | on 모드에서 warm 요청이 나가 있다 |
| `CLASSIFYING` | 에피소드 중 새 턴이 시작돼 사람 것인지 자동인지 가리는 중이다 |
| `PAUSED` | 에피소드는 열려 있지만 데우기를 쉰다. 자동 턴이 도는 중, 자식 작업이 도는 중, 아직 재개할 수 없음 중 하나다 |
| `OBSERVING` | 이 세그먼트의 데우기는 끝났다(만료나 중지 사유). 사람이 돌아올 때까지 관찰만 한다 |
| `INERT` | 아무것도 하지 않는다. mode off, print/json 모드, worker 세션, 같은 세션의 중복 인스턴스, 스스로 꺼진 인스턴스 |
| `DETACHED` | 세션이 끝났다. 재로드 복원용 상태만 남는다 |

install, update, uninstall은 `BUSY`, `PINGING`, `CLASSIFYING`인 세션이 있으면 거부한다. omo-health가 보는 세션 상태도 idle이 아니거나 도구를 실행 중이면 바쁜 것으로 본다.

## doctor 결과

doctor는 FAIL이 하나라도 있으면 1로 끝난다.

| 점검 | PASS | WARN 또는 FAIL일 때 |
|---|---|---|
| `node >= 24` | Node 24 이상 | FAIL: Node를 올린다 |
| `home writable` | 데이터 폴더에 쓸 수 있다 | FAIL: 경로와 권한을 확인한다 |
| `config` | mode를 보여 준다 | FAIL: config.json이 없다. install을 실행한다. WARN: 잘못된 필드를 기본값으로 바꿔 쓰는 중이다. 필드를 고친다 |
| `current release` | 현재 릴리스 버전과 폴더 | FAIL: current.json이나 릴리스 폴더가 없거나 파일이 빠졌다. install을 실행한다 |
| `last known good` | 이전에 로드된 버전, 또는 현재 버전이 이미 로드됨 | WARN: 아직 어떤 세션도 이 릴리스를 불러오지 않았다(설치 직후에는 정상). FAIL: lkg 폴더가 없다 |
| `stub` | 스텁이 템플릿과 같다 | FAIL: 스텁이 없다. WARN: 템플릿과 다르다. 둘 다 install로 고친다 |
| `stub.log (24 h)` | 줄이 없다 | WARN: 스텁이 current와 lkg를 모두 못 불러왔거나 진입점이 실패했다. 마지막 줄을 본다 |
| `errors.log (24 h)` | 줄이 없다 | WARN: 확장 안에서 오류가 났다. 마지막 줄을 본다 |
| `_global status` | 최근 스냅샷 한 줄 | WARN: 아직 없음(세션이 불러오기 전) 또는 오래됨(열린 세션이 없음) |
| `builtin keep-alive` | 꺼짐 | WARN: settings.json에서 senpi 내장 keepalive가 켜져 있다. keepwarm은 그 세션에서 데우지 않는다(`duplicate_warmer`) |

## 자주 보는 상황

- **install이나 update가 3으로 끝난다.** 다른 세션이 바쁘다. 출력에 세션 id와 이유가 나온다. 명령을 부른 세션 자신은 `PI_SESSION_ID`로 빠진다. 그 세션이 한가해진 뒤 다시 실행한다. `--force`는 바쁜 세션을 재로드시킬 수 있어 쓰지 않는다.
- **처음 install 뒤 열린 세션이 재로드된다.** 새 스텁 파일이 생기면 senpi가 한가한 세션부터 확장을 다시 불러온다. 그때 `session` 기록과 `app/loaded/<버전>`이 생긴다. 바쁜 세션은 한가해진 뒤에 불러온다.
- **update 뒤에도 옛 버전이 돈다.** update는 스텁을 바꾸지 않아 열린 세션을 재로드하지 않는다. 새 세션이나 다음 재로드부터 새 버전을 쓴다. 세션이 쓰는 버전은 `status/<sessionId>.json`의 `keepwarmVersion`에 있다. 새 버전을 불러오지 못하면 스텁이 lkg 버전으로 되돌아간다.
- **errors.log에 `stale extension generation after reload`가 있다.** 재로드 때 은퇴한 이전 확장 세대에 늦게 도착한 이벤트다. 해가 없고, 그 인스턴스만 꺼진다. 커밋 b060ee5(릴리스 `0.1.0+02203bd3`)부터는 기록하지 않는다. 그 전 버전이 남긴 줄은 24시간이 지나면 doctor와 스냅샷에서 빠진다.
- **omo-health의 keepwarm 줄이 warn이다.** 오늘 errors.log에 줄이 있거나 스스로 꺼진 세션이 있다. doctor와 errors.log를 본다.
- **omo-health에 `keepwarm: unknown (stale)`이 보인다.** 스냅샷이 15분 넘게 갱신되지 않았다. keepwarm을 불러온 세션이 없거나 모두 꺼졌다.
- **기록에 `skip`과 `warm_stop`이 많다.** 사유 목록은 [기록과 상태 계약](기록과-상태-계약.md)에 있다. 주력 lane(Claude 구독, Codex)은 데우기 경로가 없어서 판단만 기록한다.
- **calibrate가 2로 끝난다.** 사람 복귀가 30건 미만이다. 기록이 더 쌓인 뒤 다시 실행한다. `--write`일 때만 behavior.json을 쓴다.

## 끄기와 제거

- **잠시 끄기.** config.json의 `mode`를 `"off"`로 바꾼다. 열린 에피소드는 한 번 censored(`config_off`)로 닫히고, 그 뒤로는 기록, 상태, heartbeat를 쓰지 않는다. 다시 `"shadow"`로 바꾸면 다음 턴이 끝날 때부터 기록한다. 재로드는 필요 없다.
- **제거.** `omo-keepwarm uninstall`은 mode off를 먼저 쓰고 스텁을 지운다. 데이터는 남는다. `--purge`를 붙이면 `~/.omo-keepwarm`까지 지운다. 열린 세션은 config가 없으면 아무것도 쓰지 않으므로 지운 폴더가 다시 생기지 않는다.
- **켜기(on).** 검증된 lane에서만 실제 핑을 보낸다. 절차는 [활성화 단계](유휴-캐시-만료-정책.md#shadow에서-활성화로-가는-단계)에 있다.
