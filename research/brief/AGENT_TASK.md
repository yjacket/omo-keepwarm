# Rollover 유휴 정책 v2 — AI 에이전트 실행 지시서

**의뢰 목적:** 캐시 데우기·파킹·만료를 비교하는 기존 연구를 실제 확장에 적용할 수 있도록, 계측과 계산 엔진을 보완하고 기록 전용 연동까지 구현한다.

**이번 작업의 실행 범위:** 기존 자료·로컬 로그 분석, 코드 수정, 로컬 테스트, shadow 연동, 실험 실행기와 계획 작성.

**이번 작업에서 하지 않을 일:** 승인 없는 추가 모델 요청·quota 소비 실험, 실제 자동 파킹/데우기 정책 변경, 배포, 사용자 세션 삭제. 새로운 최적성 증명이나 minimax 논쟁을 필수 경로로 만들지 않는다.

---

## 1. 최종 목표와 이번 완료 범위

최종 목표는 **같은 작업을 제대로 완료한다는 조건에서, 유휴 시작부터 작업 완료까지의 총 quota 낭비를 줄이는 자동 정책**이다.

- 비용에는 데우기, 부모 인수인계 생성, 후속 복원, 복귀 후 본 작업과 추가 rollover를 포함한다.
- 돌아오지 않은 작업에도 이미 발생한 데우기·부모 생성 비용은 포함한다.
- 중요한 맥락, 사용자 재설명 부담, 복귀 지연은 별도의 품질 조건으로 보호한다.
- `KEEP_WARM`, `PARK`, `LET_EXPIRE`를 비교한다. `LET_EXPIRE`는 원문 삭제가 아니라 추가 갱신 요청을 하지 않는다는 뜻이다.
- 비용 교차점은 표시·검토용이다. 누적 지출이 교차점을 넘었다는 이유만으로 파킹하지 않는다.

이번에는 **실측 근거 추적 → 비용 모델 보완 → 안전한 shadow 연동 → 재현 가능한 검증**까지 완료하라. 현재 자료만으로 확정할 수 없는 계수와 운영 허용치는 미확정으로 남겨라. 미확정 항목 때문에 독립적으로 가능한 구현·테스트까지 중단하지 마라.

## 2. 자료를 읽는 순서와 신뢰 기준

동봉 자료의 경로는 전달 패키지 기준이며, 실제 저장소의 경로를 뜻하지 않는다.

1. `references/latest-review/reply-review.md`: 최근 검토와 남은 문제.
2. `references/v1/src/cache-policy.ts`: 기존 비용 모델·DP·가드·예산 제한.
3. `references/v1/tests/cache-policy.test.cjs`: 기존 동작의 검증 사례.
4. 필요한 경우 `references/comparison/comparison-review.md`, `references/v1/research-report.md`.
5. `references/claude-checks/`의 Python과 출력, `references/latest-review/audit_reply.py`: 비교·반례 자료.

증거를 다음처럼 구분하라.

| 구분 | 취급 |
|---|---|
| 원시 요청 usage·quota 시계열·실행 기록 | 관측 근거. 중복·지연·다른 요청 혼입을 확인한 뒤 사용 |
| 사용자가 제공한 집계 | 보고된 관측. 원시 근거 미확인 여부 표시 |
| API 가격 또는 공식 문서 | API 동작/가격의 근거. OAuth quota의 실측으로 대체하지 않음 |
| 기존 문서·CLI의 `costUSD` | 참고값. 최신의 정확한 계수라는 보장 없음 |
| Python/TypeScript 계산 결과 | 입력한 모형의 산술 검증. 입력 계수의 실측 검증은 아님 |

`Opus 5`, `Fable 5.1`, lane 이름은 우선 조사 자료의 표시명으로 취급하고 실제 요청의 model ID·provider·인증 경로와 대응시켜라. 기존 문서의 가격표를 현재 사실로 무조건 복사하지 마라. 공식 확인이 필요한 항목은 현재 공식 1차 출처와 확인일을 기록하되, 확인할 수 없으면 미검증으로 남긴다.

**이미 합의한 방향:** 기존 DP 유지, 생성비와 복원비 분리, 미복귀/관측 중 구분, 단일 h 임계값을 최적 정책으로 사용하지 않음, 일반적인 2배 비용 보장 주장 제거.

## 3. 권한·범위·작업 방식

### 허용된 작업

- 현재 작업 저장소와 의뢰에 해당하는 로컬 로그를 읽는다.
- 기존 테스트를 실행하고, 관련 모듈·테스트·문서를 최소 범위로 수정한다.
- 오프라인 집계·리플레이·독립 산술 검산을 실행한다.
- 기록 전용 어댑터와 기본 dry-run 실험 실행기를 만든다.

### 금지 및 승인 경계

- 계측 목적으로 실제 계정에 추가 핑, 긴 출력, 합성 cold 요청 또는 유료 API 요청을 보내지 마라.
- 현재 운영의 핑 주기·파킹 동작·예산 rollover 설정을 바꾸지 마라.
- `shadow`의 판단은 로그에만 남긴다. 기존 실행 정책을 대신하지 않는다.
- 계정·모델 전환, 인증 설정 변경, production 재시작, 배포, 자동 작업 예약을 하지 마라.
- 원문 대화·worktree·사용자 변경을 삭제하거나 덮어쓰지 마라. 전역 `AGENTS.md`, 공통 모델 설정, 무관한 플러그인은 수정하지 마라.
- 토큰·쿠키·API 키·개인 프롬프트 원문을 보고서에 포함하거나 외부로 전송하지 마라.

먼저 저장소의 실제 관련 경로와 현재 변경 사항을 확인하라. 필요하면 작업 범위가 겹치지 않는 분리 작업 공간을 사용한다. 병렬화는 서로 다른 파일을 다루는 로컬 분석·테스트에 한정하고, quota/TTL 실험을 같은 계정에서 병렬 실행하지 않는다.

저장소나 raw 로그가 없으면 그 사실을 기록하라. 저장소가 없을 때는 동봉 참조 구현에서 가능한 작업을 수행하고, 실제 확장 연동은 `BLOCKED: repository unavailable`로 보고한다. 무관한 저장소를 추정해 고치지 않는다.

## 4. 작업 A — 계측 근거와 모델·lane 비용표

### A1. 원시 usage 보존 및 중복 없는 집계

최소한 다음 원시 사용량을 별도 필드로 보존하라.

```text
uncachedInput
cacheWrite5m
cacheWrite1h
cacheRead
billedModelOutput
```

실제 응답 스키마를 확인해 겹치지 않도록 매핑한다. 이미 분리된 입력에서 캐시 입력을 다시 빼지 않는다. 스트리밍 증가분과 최종 합계, compaction iteration과 상위 합계를 중복 집계하지 않는다. 요청이 여러 번 있었다면 요청별로 한 번씩 집계한다.

도구 반환 텍스트는 다음 모델 요청의 입력이다. 이를 모델 출력으로 중복 계산하지 않는다. 요약 문서의 길이와 청구된 모델 출력량을 분리한다.

집계 단계는 다음처럼 구분한다.

| phase | 경계 |
|---|---|
| `warm` | 유휴 갱신에 사용한 요청과 그 하위 호출 |
| `park_parent` | 파킹 지시부터 handoff 저장·검증 완료까지 |
| `restore_child` | 실제 복귀 후 후속 시작부터 첫 실질 작업 직전까지 |
| `resume_raw` | 원문 경로의 동일한 작업 재개 준비 구간 |
| `useful_work` | 공통 정의의 첫 실질 작업부터 해당 작업 완료까지 |

첫 실질 작업은 단순한 첫 응답/첫 도구 호출이 아니라 작업별로 정의한 편집·명령·검증 등의 시작이다. 정의와 경계 이벤트를 기록하고 모든 경로에 동일하게 적용한다.

### A2. 비용 계수는 모델·lane별로 명시

기본 환산형은 다음과 같다.

```text
Q = k_input * uncachedInput
  + k_write5 * cacheWrite5m
  + k_write60 * cacheWrite1h
  + k_read * cacheRead
  + k_output * billedModelOutput
```

계수 레코드에는 다음을 포함한다.

```text
modelId, provider, authLane, ttlLane, effortOrConfigIdentity,
quotaMeterOrCostUnit, validFrom, measuredAt,
sourceKind, evidenceRef, sampleCount,
coefficients, observedRangeOrUncertainty, status
```

`sourceKind`는 최소 `measured`, `reported_unverified`, `api_assumption`, `unknown`을 구분한다. 날짜나 effort가 가격을 바꾼다고 전제하지 말고, 다른 조건의 측정을 혼합하지 않기 위한 식별자로 보존한다.

- 5분 쓰기 계수를 1시간 lane의 기본값으로 조용히 사용하지 않는다.
- 서로 다른 모델의 쓰기 환산값을 공통 quota인 것처럼 합산하지 않는다. 부모와 후속 모델이 다르면 공통 측정 단위로 변환하거나 비교 불가로 표시한다.
- 실제 quota가 여러 제한 창으로 나뉘면 각 meter를 보존한다. 근거 없이 하나의 스칼라로 합치지 않는다.
- 원시 usage는 불변으로 저장하고 환산 결과에는 적용한 계수 버전을 남긴다.
- API 가정만 확보한 경우 실제 quota를 확정한 것처럼 표시하지 않는다.

### A3. 이번에 확인할 구체적 항목

| 항목 | 해야 할 일 |
|---|---|
| Fable 쓰기 6틱/8틱 | `raw.jsonl`이 있으면 `fable.WR.end` 부근의 지연된 `+0.02`를 앞뒤 요청·quota 시각·리셋 경계와 함께 재집계한다. raw가 없으면 판정 보류 |
| 출력 quota | 기존 Ot 블록이 있으면 읽기·쓰기 기여를 분리해 검토한다. 없으면 실험 계획만 작성 |
| Fable 읽기/쓰기 비율 | 보고된 0.022와 범위를 원시 관측으로 확인한다. 범위의 통계적 의미가 불명확하면 신뢰구간이라고 부르지 않는다 |
| 복원 비용 | 추정치 `Rw=6K`, `Rr=125K`를 실측으로 취급하지 않는다. phase별 실제 write/read/output 합으로 대체 |
| 시스템·스킬 | S·H·복원·스킬이 서로 다른 표에서 중복 포함됐는지 대조 |
| 파킹 생성 | 부모의 큰 컨텍스트 읽기 횟수, 출력량, 각 호출의 hit/write를 분리 |

quota 표시값은 지연·반올림·리셋·동시 요청의 영향을 받을 수 있으므로, 어느 구간에 귀속시켰는지 근거를 남겨라. 현재 기록만으로 하나의 원인을 고를 수 없으면 두 가설을 유지한다.

**산출물:** 출처를 추적할 수 있는 비용 계수표, 요청/phase별 집계, 미확정 목록. 문서 수를 늘리기보다 재현 명령과 원시 기록 식별자를 남겨라.

## 5. 작업 B — 기존 계산 엔진과 시간축 보완

### B1. 기존 DP 유지

입력 계수와 캐시 상태 모델을 보완하되, 이미 구현된 DP를 단일 `h*` 규칙으로 교체하지 않는다. 이미 발생한 데우기 비용은 미래 기대비용 최소화식에 넣지 않는다. 과거 지출은 별도의 예산 가드에서만 사용한다.

한 번의 판단은 실제 사용자/작업 활동이 없는 시점에서 수행한다. 캐시가 아직 안전하게 남아 있으면 추가 요청 없이 기다리는 행동을 보존한다.

### B2. warm/cold는 요청이 도착할 때의 상태로 계산

다음 정보를 구분하라.

```text
lastMeaningfulActivityAt
lastVerifiedCacheRequestStartedAt
cacheExpiresAt / prefix-level evidence
requestArrivalDelay / safetyMargin
sessionGeneration / model-lane-prefix identity
```

- 데우기를 의미 있는 사용자 활동으로 기록하지 않는다.
- 잔여 TTL과 요청 지연을 비교해 warm, cold, uncertain을 구분한다.
- 파킹뿐 아니라 데우기에도 늦은 도착에 따른 재쓰기 비용을 반영한다.
- 일부 공유 prefix만 살아 있는 경우와 전체 miss를 분리한다.
- 부모 첫 호출만 cold인 경우와 여러 호출이 다시 만료되는 경우를 같은 상수로 뭉개지 않는다.
- 관측 근거 없이 hit 가능성을 임의의 확률로 만들지 않는다. uncertain은 시나리오 범위 또는 실행 차단 사유로 표시한다.
- 서로 다른 TTL prefix를 단일 TTL로 다룰 수 없다면 지원 범위를 명시하고 자동 실행을 차단한다.

실패·거부·모델 폴백·재쓰기는 별개의 상태 전이다. `stop_reason` 하나만으로 캐시 사망, 무료 요청, TTL 갱신을 확정하지 않는다. 실제 usage와 응답 모델·시간·prefix 근거를 같이 기록한다. 이번 작업에서는 자동 재시도 요청을 발행하지 않는다.

### B3. 미래 절약 V와 품질 조건

미래 절약은 선택적인 입력으로 추가한다. 복귀당 복원 B, 정보 손실 L, 이후 절약 V를 사용하는 단순한 표현은 다음과 같다.

```text
parkExpected = G + q * E[B + L - V | return]
```

실제 DP에서는 복귀 시각에 따른 상태 차이도 반영한다. 이 식을 이미 파킹/원문 양쪽의 전체 미래 작업 비용을 합산한 계산에 또 적용하지 않는다.

- B에 들어간 복원 호출과 V의 절약 호출을 중복 계상하지 않는다.
- 유지·파킹 경로를 같은 작업 완료 지점에서 비교한다.
- 원문 경로가 예산 rollover로 축소되는 시점 이후에는 큰 C와 작은 C의 차이를 계속 누적하지 않는다.
- C′, 남은 호출 수, 예산 rollover 시점이 미검증이면 실제 quota 절감으로 보고하지 않는다. V=0 기준과 선택적 추정 시나리오를 따로 출력한다.
- V는 quota 환급이 아니라 경로 간 미래 비용 차이다. 원시 청구값은 음수가 될 수 없고, 부호 있는 비교 차액은 별도 필드로 관리한다.
- 종료 제약·승인 조건·미완료 상태 보존은 금액화 이전의 파킹 허용 조건으로 둔다.
- 기존 Cb에서 역산한 Λ는 정책 보정값이지 정보 손실 실측값이 아니다.

### B4. 예측 없음과 운영 미확정값

복귀 예측이 없으면 `q=1` 또는 `q=0.5`를 사실처럼 넣지 않는다. shadow에서 `no_calibrated_forecast`를 기록하고, 기존 v1의 만료 제안 또는 별도 승인된 유한 예산 시나리오를 표시한다. **기존 운영의 실제 핑을 중지하라는 뜻이 아니다.**

minimax는 이번 필수 구현 범위가 아니다. 붙이더라도 실험적 비교 모드로만 두고 기본값·최적성 보장을 바꾸지 않는다.

다음 값은 사용자 승인 설정으로 분리한다.

```text
maxProactiveSpendPerIdle
maxTotalExperimentalSpend
maxResumeDelay
allowedQualityDegradation
minimumEvidenceForEnforcement
```

단위와 의미를 명시하되 승인되지 않은 숫자를 임의로 채우지 않는다. 값을 알 수 없으면 `unconfigured`로 두고 실제 신규 정책 실행은 불가 상태로 유지한다. 0을 ‘무제한’과 ‘미설정’ 양쪽 의미로 사용하지 않는다.

## 6. 작업 C — 실제 확장의 shadow 연결과 유휴 로그

### C1. 작동 모드

| 모드 | 의미 |
|---|---|
| `off` | 신규 정책 비활성. 기존 동작 유지 |
| `shadow` | 기존 동작 유지 + 신규 정책의 비용·선택을 로컬 기록 |
| `enforce` | 이번 작업에서는 활성화하지 않음. 필요 조건과 승인 가드만 문서화 |

새 정책은 자체적으로 모델 호출을 보내거나 세션을 교체하지 않는다. 기존 이벤트·타이머를 활용하고 중복 갱신 타이머를 만들지 않는다. 실제 통합이 어려우면 어댑터 인터페이스와 기록 리플레이까지 구현하고 미연결 상태를 명시한다.

의사결정 로그에는 최소 다음을 남긴다.

```text
idleEpisodeId, timestamp, sessionGeneration,
modelId, lane, contextTokens, remainingTtlMs, cacheStateEvidence,
costCoefficientVersion, forecastVersion, parameterSources,
candidateCosts, recommendedAction, currentPolicyAction,
reasonCode, guardReasons, incurredSpendSoFar,
VScenario, evidenceStatus
```

부가 보존 데이터는 토큰 길이·이벤트·안전한 식별자 위주로 하고 대화 본문 전체를 새로 복제하지 않는다.

### C2. 복귀 로그

- 실제 활동의 시작/종료, 다음 실제 복귀 시각, 작업 종료 사유를 기록한다.
- 데우기를 복귀로 세지 않는다.
- 질문 대기/완료 보고/진행 중 등의 상태와 시간대를 기록할 수 있게 하되, 불필요한 사용자 프로파일링은 하지 않는다.
- 관측 종료까지 미복귀인 세션은 오른쪽 검열이다. 명확한 작업 종료와 구분한다.
- 예측 기간 밖의 복귀 꼬리를 ‘영원히 안 돌아옴’으로 바꾸지 않는다.
- 표본이 부족하면 예측 가능으로 표시하지 않는다. 생존함수를 만들더라도 유한한 관측만으로 영구 미복귀율이 자동 확정되는 것은 아니다.
- 리플레이에서는 해당 시점까지 알 수 있던 데이터만 예측 입력에 사용한다. 실제 미래 복귀 시각을 미리 넣은 결과는 oracle/시뮬레이션으로 별도 표기한다.

## 7. 작업 D — 승인 후 실행할 실험 준비

아래 실험은 **계획·실행기·분석기까지만 준비**하라. 이미 승인된 범위가 별도 자료로 확인되지 않는 한 실제 요청은 보내지 않는다.

| 실험 | 설계의 필수 요소 | 확인할 결과 |
|---|---|---|
| 출력 quota | 입력/읽기/쓰기 기여 분리, 출력량 여러 수준, quota 창·동시 요청 통제 | 출력 계수의 관측 범위와 식별 가능 여부 |
| Fable 쓰기 tick | 이전/이후 지연된 계기판 변화까지 저장, 다른 요청·리셋과 분리 | 6/8틱 해석과 증거 |
| 1h TTL 갱신 | 같은 길이의 서로 다른 고유 prefix. 처리군 t=0 쓰기, t=55분 핑, t=110분 검사. 대조군 t=0 쓰기 후 t=110분 검사 | target prefix의 hit/write 차이, 실제 TTL lane, 관측 오염 여부 |
| 복원 분해 | phase 경계가 있는 요청별 usage, 시스템·스킬 중복 검사 | 실제 read/write/output과 복원 종료점 |
| 정책 효과 | 같은 작업·동일 복원 범위, 기존 정책과 신규 정책을 구분한 제한적 대조 | 총 quota, 실제 재개 지연, 실패·재설명·재작업 |

TTL 실험은 중간 probe 자체가 캐시를 갱신할 수 있으므로 불필요한 검사를 추가하지 않는다. 공통 시스템 prefix hit를 고유 실험 구간의 hit로 잘못 해석하지 않는다. 지연/오류로 조건이 깨진 실험은 무효 또는 별도 실패로 기록한다. 단일 관측으로 모든 세션에서의 보존을 보장하지 않는다.

실행기는 기본 `dry-run`으로 동작하고 예상 요청 수·소비 범위·총예산 상한·중단 조건을 출력해야 한다. 계수를 모르면 확정 quota 견적이라고 표현하지 않는다. 실제 실행 권한이 없는 상태에서는 예약·백그라운드 대기·시간 경과 실험을 시작하지 않는다.

실행 승인에 필요한 내용을 `측정 항목 / 호출 계획 / 예산 단위·상한 / 중단 조건 / 미실행 시 영향` 표로 남긴다.

## 8. 검증·회귀 테스트·완료 판정

### 기존 계산의 재현

단위를 명시하고 원래 테스트를 실행한다. 아래 fixture는 **실제 계수 확정값이 아니라 수학적 회귀 입력**이다.

```text
단위: 쓰기 환산 K토큰 (엔진이 tokens이면 ×1,000)
a=A=8.25, G=24, B=16.75, K=150
각 다음 구간의 무조건 복귀 확률=[0.10, 0.05, 0.03, 0.02]
영구 미복귀 확률=0.80
조건: 현재 무료 잔여 TTL은 무시할 수 있음; 핑 성공; 미래 절약 없음
```

- `PARK` 기대비용 27.350K, `WARM→EXPIRE` 기대비용 24.075K, DP는 후자를 선택해야 한다.
- K만 126.375K로 바꾸면 DP 비용은 21.7125K다. 이 경우 원래 h 규칙도 WARM을 선택하므로 ‘같은 반례가 유지됨’이라고 주장하지 않는다.
- minimax 검산에서 첫 구간 무료 여부와 첫 핑 비용을 동일한 시간축으로 맞춘다. 단순 시뮬레이션 일치율을 일반적 최적성 증명으로 쓰지 않는다.

### 반드시 추가할 검증

| 영역 | 필수 사례 |
|---|---|
| 비용 | 5m/1h 계수 분리, 다른 단위 혼합 거부, unknown 계수 표시, 정규화 단위 변경 시 선택 불변 |
| 집계 | 스트리밍/최종 합계 중복 방지, iteration 중복 방지, 도구 결과와 모델 출력 구분 |
| 시간 | TTL 충분/마감/만료, 사용자 복귀와 타이머 동시 발생, 잔여 TTL보다 요청 지연이 큰 경우 |
| 캐시 | 전체 hit·부분 hit·miss, 부모 첫 호출 cold, 모델/lane 변경, 거부와 실제 재쓰기 구분 |
| 의사결정 | 대안 전환 반례, 작은 C에서 cold 우세, 미복귀, 예측 없음, 매몰비용 배제 |
| 미래 절약 | V=0이면 기존 결과 보존, 복귀 확률 적용, B/V 중복 방지, 양쪽 rollover 구간 일치 |
| 품질 | 파킹 불허 조건 우선, 손실 설정 없음과 손실 0의 차이 표시 |
| 실행 안전 | shadow에서 신규 모델/API 호출 0회, 실제 전환 0회, 사용자 작업 우선, 중복 타이머 방지 |

독립 검산은 테스트 기대값을 본 엔진에서 다시 계산해 만드는 방식만 사용하지 마라. 소규모 시나리오를 독립적인 재귀/전수 정책 비교로 확인하고, 그 모형의 범위를 명시한다. 테스트를 실제로 실행한 환경·명령·결과를 기록한다.

### 이번 작업 완료와 배포 준비를 구분

**이번 작업 완료:** 가능한 raw 분석, 비용 모델 수정, 로컬 테스트, shadow 또는 명시된 어댑터 구현, 실험 계획, 미확정·승인 목록이 재현 가능하게 남음.

**배포 준비 완료는 아님:** 총 quota 절감, 실제 업무 품질, 허용 지연, 실측 계수·TTL의 충분한 근거는 이후 승인된 대조 실험으로 검증해야 한다. shadow만으로 선택하지 않은 행동의 실제 효과를 입증했다고 말하지 않는다.

## 9. 산출물과 최종 보고 형식

실제 저장소 규칙에 맞춰 경로를 정하되, 가능한 한 다음 자료로 통합하라.

1. **코드·테스트 변경:** 비용 계층, 캐시 상태, DP 보완, shadow 어댑터, 집계/실험 실행기. 불필요한 전면 재작성 금지.
2. **근거 묶음:** 계수표, phase 집계, 재현 명령, 테스트 결과, shadow 샘플. 민감한 원시 데이터 제외.
3. **실행/연구 문서:** 결정된 사항, 미확정 사항, 실험 계획, 실제 실행에 필요한 승인 조건, 복구 방법.
